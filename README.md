# boss-cli

BOSS 直聘命令行工具，支持扫码登录、搜索岗位、查看详情，以及检查或发起与 HR 的沟通。使用项目专用 Chrome profile 保存登录态，通过原生 CDP 操作普通 Chrome。

**2026-09-06 已在 macOS 的真实登录态下完成登录核验、搜索、详情、建立联系及当前弹窗单条文本发送；重新打开会话后确认该条消息显示“送达”。** 本次为共用 context 的受控测试，独立 CLI 的自定义消息会话仍未完成适配。使用真实 Chrome 不能保证平台接受自动化访问。

## 安装

需要 **Node.js 22 或更高版本**及本机安装的 **Google Chrome**。

```bash
git clone https://github.com/ACM66/boss-cli.git
cd boss-cli
npm install
node bin/boss.js --help
```

可选运行 `npm link` 注册 `boss` 命令；以下示例中的 `boss` 也可以换成 `node bin/boss.js`。

找不到 Chrome 时，将 `BOSS_CHROME_PATH` 设为浏览器可执行文件的绝对路径。运行时使用本机 Chrome，不需要安装 Playwright 的浏览器，也不会自动下载浏览器。Windows / Linux 尚未完成端到端验证。

## 使用

```bash
boss login                                  # 打开登录页，切到扫码入口并生成扫码文件
boss whoami                                 # 核验页面登录态
boss status                                 # 离线查看暂停时间、累计用量和策略
boss open                                   # 打开专用 Chrome；优先展示已有页面，交给你操作
boss open --existing-only                   # 只展示已打开的页面，没有就停止，不访问首页
boss search "后端工程师" -c 北京 -n 3          # 最多输出本页的 3 个岗位
boss show '岗位URL或加密id'                  # 读取岗位详情
boss greet '岗位URL或加密id' --dry-run        # 检查详情和沟通按钮，不点击、不发送
boss logout                                 # 不导航业务页面，清理本地登录态和岗位缓存
```

需要实际联系 HR 时，可以运行以下命令；它会建立真实联系，并可能按平台当前设置自动发送招呼语。该路径已做单岗位真实验收，仅在明确需要联系该岗位时使用。

```bash
boss greet '岗位URL或加密id'
boss greet '岗位URL或加密id' --dry-run -m '您好，我对这个岗位很感兴趣'  # 只预览
```

- `login` 默认等待 600 秒，可用 `--timeout <秒数>` 设置 1–1800 秒。**登录页默认展示的是短信验证码表单，二维码要先点扫码入口才渲染**，命令会按 `.sign-tab .link-scan`、`.ewm-switch`、`.wx-login-btn` 等已观察到的入口逐个切换，切一次等一次真实加载的二维码。取到后写入 `~/.boss-cli/qr.png` 和自动刷新的 `qr.html`；**扫码方式（BOSS 直聘 APP 还是微信）读页面自己的提示原文，不写死**。二维码失效时会点页面上的「点击刷新」换新码。
- 页面确实不给二维码时不再报错退出：保存 `login-diagnostic.png`、列出试过的入口，并把专用 Chrome 窗口调到前台，等你在窗口里用页面提供的方式（短信验证码等）自行登录，登录成功后命令继续接管并持久化登录态。工具不代收、不代填手机号和验证码。
- `search`、`show` 和 `greet` 默认使用可见窗口；`search` / `show` 的 `--show` 保留为兼容选项。`--headless` 可显式请求无头启动，但尚未验证其在 BOSS 页面的兼容性。复用已登记浏览器时保留它原来的显示模式。
- `--city` 接受支持的城市名或 9 位城市编码，默认全国；未知名称会报错。
- `--limit` 接受 1–100，默认 20，表示最多输出条数。**目前只取当前一页，不自动翻页；本次实测一页 15 条，指定更大的 limit 不会补足结果。**
- `BOSS_JSON=1` 让 `search` / `show` 输出 JSON；成功的零结果输出 `[]`。过程日志写入 stderr，读取或解析失败以非零退出码结束。
- `BOSS_DEBUG=1` 开启调试日志。`show` / `greet` 需要具体的 `zhipin.com/job_detail/…html` 链接或加密岗位 ID，不能传任意页面。
- 搜索和详情默认复用 5 分钟内的成功结果，缓存命中会在 stderr 显示原读取时间；`--fresh` 可刷新，但仍受额度和冷却限制。`greet` 始终核对真实页面，不用缓存执行写操作。

以下为截至 2026-09-06 的验证范围。真实站点验证仅覆盖一次账号会话和少量岗位；本地测试覆盖失败与退出分支，不能证明长期运行不受限。

| 命令 | 验证结果 |
| --- | --- |
| `whoami` | 输出 `logged_in`，退出码 0 |
| `search "后端工程师" -c 北京` | 取得一页 15 条真实岗位，岗位与薪资可读 |
| `show` 搜索得到的岗位 URL | 岗位名、公司、薪资与搜索结果一致，职责非空 |
| `greet --dry-run` 同一岗位 | 详情一致、沟通按钮可用，输出 `sent: false`，退出码 0 |
| `greet` 建立联系 | 单岗位接口成功，并出现对应招聘方的沟通弹窗 |

| `open --existing-only` | 复用已登录页面、不重新导航；窗口保留、锁释放，退出码 0 |
| `status` | 只读本地冷却和额度，无站点访问 |
| `login` / `logout` | 人工登录后持久化复用已验证；扫码入口选择器取自 2026-09-06 线上登录组件真实 DOM，切换与刷新逻辑有真实 Chrome + localhost 回归，**登出态下的完整重新扫码尚未验收**（需要先退出当前会话才能观察）；真实账号退出登录也未验收，站点存储清理有本地 Chrome 测试 |

2026-09-06 的补充验收选择了一家页面标注 0–20 人的公司。为遵守仅发送 `test` 的要求，测试先临时关闭自动招呼语并回读确认；`greet` 服务端确认建立联系后，在岗位详情的沟通弹窗发送一次 `test`，取得消息 ID。新打开的完整会话显示唯一一条 `test` 和“送达”；随后恢复原自动招呼语开关及模板并回读一致。

实际 `greet` 仅在建立联系接口返回成功后报告 `contact_established`，默认招呼消息送达仍标记 `unverified`。自定义文本目前只支持 JS 入口传入同一个 `context`、且已确认建立联系的岗位详情弹窗；它校验公司、输入、消息状态和消息 ID，发送意图另存 `message-intents/` 以阻止重发。**独立 CLI 的 `greet -m` 仍仅支持 `--dry-run` 预览**，完整消息页尚未适配，不能将本次当前弹窗的成功扩展为所有发送路径均已验收。

## 浏览器与访问控制

- **打开 BOSS 网页统一使用 `boss open`。** 它先检查冷却与专用 profile 的会话 Cookie，再核验页面登录态，优先激活该 profile 中已有的 BOSS 页面而不刷新；没有现有页面才受控访问首页。未登录时提示 `boss login`，不会改用侧边浏览器或系统默认浏览器。它不接受任意 URL，也没有跳过登录或冷却的开关。
- 不同浏览器的登录环境和访问结果不能混用。项目级 [AGENTS.md](AGENTS.md) 固化了打开入口、禁止替代浏览器、异常证据核对和测试约束。规则约束本项目的操作流程，不能拦截用户或其他应用自行发出的请求。
- 使用 `~/.boss-cli/userdata` 专用 profile。存在有效 `browser.json` 记录时，先核对进程、profile 和调试端口归属，再复用该浏览器；未登记或不匹配的浏览器不会被接管。
- 命令自己启动的 Chrome 会在结束时关闭；复用的浏览器进程保持运行。`browser.lock.json` 保证同一时间只有一个 boss 命令操作这个 profile，并发命令会明确报错。
- `boss open` 成功后调用 `context.handoff()`，保留专用 Chrome 和页面，断开自动化连接并释放锁；下一条 CLI 命令仍可核验并复用该浏览器。交接后的手工浏览不受 CLI 自动限频监控，遇到受限提示仍应停止。已有实例为无头模式时明确报错，不切换到其他浏览器。
- 登录、登录核验、搜索、详情、沟通中的主动导航统一通过 `AccessGuard`；临时工具直接调用本项目 `page.goto()` 也受约束。状态保存在 `access-state.json`，跨命令和进程共享；损坏时明确停止。
- 默认主动导航间隔 15 秒，每滚动小时最多 30 次、滚动 24 小时最多 200 次；写操作间隔 60 秒，滚动 24 小时最多 10 次。窗口额度耗尽会立即退出，不自动排队等待整小时。**这些是本工具的保守预算，不是 BOSS 公布或验证过的安全阈值。**
- 主 frame 每分钟超过 8 次实际导航，或网页自身每分钟超过 120 次 BOSS 业务接口响应，会触发暂停。接口响应计数是事后保护，不等于在请求发送前精确限制全部 HTTP；普通资源和 DOM 读取不计业务接口额度。
- 发现明确访问限制、人工验证页面或相关 HTTP 403/429，立即停止自有页面加载、阻断后续请求、结束所有等待。默认暂停 30 分钟；能读到平台恢复时间或 `Retry-After` 时，至少遵守其时间并加 5 分钟缓冲。已有较晚暂停时间不会被缩短。未取得平台恢复时间时，本地默认暂停不代表平台届时一定恢复。
- 暂停检查先于启动或连接 Chrome，重启 CLI 不会清掉暂停。`boss status` 只读本地状态，不会探测网站；系统时间倒退、记录损坏等异常也会停止访问。
- 累计额度从启用该策略后开始记录，不会把此前不完整日志反推成准确的历史访问量。
- 可在 `~/.boss-cli/access-policy.json` 用 JSON 覆盖 [src/config.js](src/config.js) 中 `ACCESS_POLICY` 的同名参数，例如 `{"navigationIntervalMs":30000,"maxNavigationsPerHour":15}`。未知字段或非法值会报错；没有忽略冷却的命令行开关。
- 一项任务可在 `whoami` / `search` / `detail` / `greet` 的 JS 参数中传入同一 `context`，复用自有浏览器和页面；该调用方负责最终关闭 context。相同岗位的详情与发送前检查不重复导航。独立 CLI 命令仍保留启动后清理的生命周期。
- 搜索访问 `/web/geek/jobs`，读取网页自己发起的成功岗位响应，以获得可读薪资；工具不生成签名、不重放搜索 HTTP 请求。详情从真实页面读取，并检查必要字段。运行时没有 stealth 注入。
- 出现访问限制或验证码时，按错误提示处理，避免反复重启登录或高频刷新。普通 Chrome 和随机间隔不能保证绕过平台风控。
- 沟通点击前在 `contact-intents/` 持久化岗位意图；进程中断、回执缺失、结果未知或已确认时，同一岗位均不会自动重复点击。回执需要与按钮声明的目标参数匹配。未知结果必须人工核对，不应删除记录后重试。

## 本地数据与隐私

- `~/.boss-cli/userdata` 包含登录 cookie 和页面存储，请勿提交到 Git 或分享给他人。`browser.json` 保存本地浏览器连接信息，也不要对外分享或开放调试端口。
- `~/.boss-cli/logs/boss.log` 会记录搜索关键词、岗位链接等信息；二维码及诊断截图也可能含个人信息。分享日志、截图前先检查内容。
- `read-cache.json` 仅存成功读取的岗位数据，最多保留 20 项；写操作不使用该缓存。`contact-intents/` 保存岗位 ID、时间和沟通状态，不保存会话凭证或 HR 联系信息。
- `boss logout` 禁止本工具新建页面联网，直接通过 CDP 清除本地 Cookie 和站点存储，并删除岗位缓存；清理不完整以非零退出码结束。它保留冷却和沟通记录，不会重置额度。此模式不代表操作系统或既有浏览器的其他页面断网。
- 实际 `greet` 会联系招聘方。请控制频率，遵守平台规则，不用于批量骚扰。

## 开发与维护

运行 `npm test` 执行本地回归，包括独立临时 profile 的真实 Chrome 与 localhost 服务、真实状态文件/子进程、已记录响应的解析测试；不访问 BOSS，也不等于线上端到端验收。页面字段与选择器集中在 [src/config.js](src/config.js)，验证日期对应此前实际观察的页面结构。若站点变化导致失败，再结合真实页面更新对应解析，并重新验证该能力。

在平台限制已解除且确认可正常使用后，显式运行 `npm run test:e2e`。它在一个 context 中调用 `whoami → search → detail → greet --dry-run` 的业务入口，强制刷新搜索和详情，核对一致性，并复用详情页检查沟通按钮；不发起沟通或发送消息。它验证共享会话业务链路，不是逐条子进程 CLI 测试。可用 `npm run test:e2e -- '关键词' '城市'` 指定条件，结果保存在 `log/e2e-shared/`，失败会覆盖本次 summary 状态，不沿用旧成功结论。此脚本不属于默认 `npm test`。

未来自动投递仍需接通独立 CLI 的自定义消息和完整会话页，再定义岗位筛选条件、排除公司、发送内容和额度。当前没有批量投递命令，也不会后台自动投递。

主要模块：`src/browser.js` 管理 Chrome 生命周期和命令锁，`src/cdp.js` 提供原生 CDP 操作，`src/auth.js` 管理登录，`src/jobs.js` 读取岗位，`src/chat.js` 处理沟通，`src/anticrawl.js` 管理限频和风控检测，`bin/boss.js` 提供 CLI。
